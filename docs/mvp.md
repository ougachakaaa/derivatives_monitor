# MVP：可信的单月期权 Skew 观察

目标用户是项目所有者，使用场景为本地个人盯盘与研究。完成定义：连续几个交易日通过页面完成真实市场观察，知道数据是否可信，并能追溯或回看结果。

## 固定范围

- 业务闭环：选定 **MO 一个到期月**，查看 Skew 当前水平、当日分钟变化和指定分钟回看；同时看到数据时间、质量与不能计算的原因。
- 现有采集范围保留：CFFEX IF/IH/IC/IM、TS/TF/T/TL、IO/HO/MO，以及 SHFE AU/AG 期货。分析不要求同时扩展至所有品种/月。
- C++ → Raw SQLite → Python Market State → Analytics → JSON → React 汇报页。Analytics 与汇报页是待实现能力，现有页面仍是采集诊断看板。
- 独立采集、只读消费、真实 TradingDay、时间/质量语义和本地部署边界见[架构与契约](architecture.md)。这次文档整理不改变这些边界。

## Skew 设计完成前必须冻结的口径

业务方向已确定，但公式未在已有项目中确定，不能由整理文档暗中定案。下列是同一 MVP 设计的待决项，不是额外阶段或过程任务：

| 决定 | 必须记录的内容 |
|---|---|
| Skew 定义 | delta 点位或行权价选择、看涨/看跌差值方向、单位、插值和缺翼规则 |
| 定价和标的 | 定价模型；现货、对应期货或其他参考值的来源和含义；不得把期货当现货而不披露 |
| 参考参数 | 行权价、精确到期时刻、期限计数、利率/分红等模型所需参数；来源、有效期和版本 |
| 报价与同步 | bid/ask/mid 选择、可计算性筛选、最大 age、跨合约时间差、PARTIAL 可接受条件 |
| 数值算法 | IV 求解边界、收敛条件、失败输出；独立验证方法与提前固定的误差阈值 |

冻结后直接补充本节及 Market State 下游契约。当前 CTP 不提供现货指数，Raw 的默认 usable 也不意味着可算 IV。输入不足时应显示无法计算，不能用默认利率、虚构到期日或旧报价悄悄补齐。

## 六个收尾条件

1. **真实运行**：在声明的机器、配置、合约范围下连续 3 个完整交易日，无日常人工修复，无无法解释的数据中断。AU/AG 既已纳入采集范围，需补真实夜盘开盘、跨零点、次日日盘、下一真实 TradingDay 的连续证据。
2. **可信数据**：清单、订阅、接收、陈旧、无效分别表达；缺失/过期不产出貌似正常指标；历史值有明确时间。不能要求不活跃合约固定推送，也不能把采样行数当原始 tick 数。
3. **正确指标**：完整闭环可用；至少 10 个时点独立核对，覆盖正常/异常输入与时段边界，按预定误差验收。结果能定位 Raw revision、Universe、Calendar、参数和算法版本。
4. **可用页面**：30 秒内看懂对象、水平与变化、数据时间、可信程度；连续 3 次日常观察无需 SQL/日志。诊断明细可展开，首页采用汇报模式。
5. **恢复可靠**：断线重连、异常退出后重启、Query 独立停启通过；健康失效及时显示，已提交数据保留；完成一次真实数据备份恢复并验证历史查询。
6. **可以交付**：固定验收版本；在声明支持的部署方式上可复现部署；启动/停止/更新/恢复说明齐全；阻断问题清零，其余限制可查。原生和 Docker 的证据分开记录。

性能门槛：固定机器、真实一天数据、单人使用，核心查询 P95 ≤ 2 秒；至少 100 次成功请求并记录错误数，不能把失败请求从报告中隐藏。持续活跃且输入可用时，默认 15 秒采样 + 5 秒轮询的页面接收至显示延迟目标 ≤ 30 秒；分别记录源、接收、物化与显示时间。这是待实测目标，非现有性能保证。

“核心查询”最终包括当前/指定分钟 Skew 及当天变化；已有 health/snapshot 接口通过不替代未来业务查询性能验收。验收样本需覆盖完整目标月链及积累一天后的库，不能仅测空库。

## 阻断与后续事项

错交易日、丢已提交数据、错误/不可追溯指标、旧数据假装当前、频繁人工修复、缺真实业务验收，均阻止收尾。测试全绿只证明已覆盖的工程条件。

更多品种分析、更多指标、复杂图表、自动告警、交易/策略/回测、云部署/认证、WebSocket、Dev Container 不纳入本版。Python/Node 仅在兼容性或验收阻塞时升级；依赖锁文件继续保留。数据目前已经在宿主持久 bind mount，无需为了 MVP 迁移存储。

当前状态及证据缺口见[验收矩阵](acceptance.md)。这里定义目标，不将底座验收完成改称整个产品完成。
