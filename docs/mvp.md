# MVP：可信的单月期权 Skew 观察

目标用户是项目所有者，使用场景为本地个人盯盘与研究。完成定义：连续几个交易日通过页面完成真实市场观察，知道数据是否可信，并能追溯或回看结果。

## 行情接入能力边界

项目只接入 CTP MdApi 的行情推送，不接入 TradeApi / TraderApi；不提供报单、撤单、资金、持仓或成交查询等交易接口能力。行情订阅与接收所需的 MdApi 连接/登录流程保留，不因排除交易接口而删除。此边界不缩减已有只读查询、分析与页面能力。

## 固定范围

- 业务闭环：选定 **MO 一个到期月**，查看 Skew 当前水平、当日分钟变化和指定分钟回看；同时看到数据时间、质量与不能计算的原因。
- 现有采集范围保留：CFFEX IF/IH/IC/IM、TS/TF/T/TL、IO/HO/MO，以及 SHFE AU/AG 期货。分析不要求同时扩展至所有品种/月。
- 业务结果通过[当前系统架构](../ARCHITECTURE.md)定义的采集、只读解释、分析、JSON 和汇报页面闭环交付；当前实现及证据缺口只在[验收矩阵](acceptance.md)登记。
- 长期取舍理由见[设计原则](../DESIGN.md)，精确数据、时间、质量、分析与部署行为由对应 [Contracts](contracts/) 定义。

## 业务指标边界

MVP 使用 **`mo-skew-25d-v1`** 作为唯一 Skew 指标定义。模型、远期、参考输入、时间选择、报价质量、数值求解、失败语义和验证容差的唯一完整来源是 [Analytics / Skew Contract](../query/contracts/analytics-skew.md)及其[机器策略](../query/contracts/analytics-skew-v1.json)；本文件只规定该指标必须支撑上述单月观察闭环，不复制其算法。

## 六个收尾条件

1. **真实运行**：在声明的机器、配置、合约范围下连续 3 个完整交易日，无日常人工修复，无无法解释的数据中断。AU/AG 既已纳入采集范围，需补真实夜盘开盘、跨零点、次日日盘、下一真实 TradingDay 的连续证据。
2. **可信数据**：清单、订阅、接收、陈旧、无效分别表达；缺失/过期不产出貌似正常指标；历史值有明确时间。不能要求不活跃合约固定推送，也不能把采样行数当原始 tick 数。
3. **正确指标**：完整闭环可用；至少 10 个时点独立核对，覆盖正常/异常输入与时段边界，按预定误差验收。结果能定位 Raw revision、Universe、Calendar、参数和算法版本。
4. **可用页面**：30 秒内看懂对象、水平与变化、数据时间、可信程度；连续 3 次日常观察无需 SQL/日志。诊断明细可展开，首页采用汇报模式。
5. **恢复可靠**：断线重连、异常退出后重启、Query 独立停启通过；健康失效及时显示，已提交数据保留；完成一次真实数据备份恢复并验证历史查询。
6. **可以交付**：固定验收版本；在声明支持的部署方式上可复现部署；启动/停止/更新/恢复说明齐全；阻断问题清零，其余限制可查。原生和 Docker 的证据分开记录。

性能门槛：固定机器、真实一天数据、单人使用，核心查询 P95 ≤ 2 秒；至少 100 次成功请求并记录错误数，不能把失败请求从报告中隐藏。持续活跃且输入可用时，在 Contracts 定义的默认采样与页面轮询配置下，页面接收至显示延迟目标 ≤ 30 秒；分别记录源、接收、物化与显示时间。这是待实测目标，非现有性能保证。

“核心查询”包括当前/指定分钟 Skew 及当天变化；已有 health/snapshot 接口通过不替代 Skew 业务查询性能验收。验收样本需覆盖完整目标月链及积累一天后的库，不能仅测空库。

## 阻断与后续事项

错交易日、丢已提交数据、错误/不可追溯指标、旧数据假装当前、频繁人工修复、缺真实业务验收，均阻止收尾。测试全绿只证明已覆盖的工程条件。

更多品种分析、更多指标、复杂图表、策略研究/回测、云部署/认证、WebSocket、Dev Container 不纳入本版单月 Skew 观察闭环。自动机会通知作为下述平行扩展单独交付，不增加或替代上文收尾门槛。

当前状态及证据缺口见[验收矩阵](acceptance.md)。这里定义目标，不将底座验收完成改称整个产品完成。

## 平行扩展：实时监控 / 机会发现 / 信号通知 v1

目标仍为本地个人使用：`Market State → Analytics / Feature → Monitoring Rule → Opportunity Event → Notification → Human`。系统只发现用户定义的机会并通知人，**永远不进入自动下单或交易执行链路**；这不是暂时推迟的交易功能。

首版交付一个显式 MO 月的现有 `mo-skew-25d-v1` 阈值机会检测、可恢复的事件记录和一个通用 HTTP webhook 渠道。事件能够说明规则、指标/市场输入、时间、值及原因；持续满足不无限通知；机会成立与通知投递是两个独立事实。精确行为由 [Feature](contracts/features.md)和 [Monitoring](../monitoring/CONTRACT.md) Contracts 定义。

IM basis、IM 5 分钟收益率和 MO ATM IV 是扩展性验证例子，首版只以标明 TEST DOUBLE 的 Feature 输出验证核心可复用；不将其登记为生产支持，不新增现货源或修改冻结 Skew。后续生产接入需要各自指标与输入契约。产品模型不绑定这几个例子。

完成边界为一个本地独立前台 Monitoring 进程的可恢复工程闭环，真实市场与真实通知证据另列 [Monitoring Acceptance](../monitoring/ACCEPTANCE.md)。本阶段只冻结设计和实施交接；后续实现不包含规则管理 UI、复杂 DSL、消息队列、独立通知服务、分布式系统、自动换月、历史机会补发、cooldown/持续满足等新增触发策略，也不接管现有部署或 developer runner。

平行扩展不改变原 Skew MVP 的 G1–G6、P1/P2；扩展工程通过不等于真实指标、真实通知或整个 MVP 完成。
